# macOS 一键启动器设计

## 目标

在项目根目录提供 `启动编辑器.command`。用户双击后即可启动本地微信公众号编辑器并打开浏览器，不需要手动打开终端执行 `npm start`。

## 行为

- 启动器始终以自身所在目录作为项目目录，不依赖 Finder 或终端当前路径。
- 补充 Homebrew 常用 PATH，检查 Node.js 是否存在且主版本不低于 20。
- 默认使用 `127.0.0.1:3000`，先检查健康接口和页面标识：
  - 如果当前编辑器已经运行，只打开浏览器，不重复创建进程。
  - 如果端口被其他程序占用，停止并明确提示，不结束或替换占用进程。
  - 如果端口空闲，在后台执行 `node server.mjs`，等待健康检查成功后打开浏览器。
- 日志写入忽略提交的 `data/logs/`，PID 写入 `data/runtime/`。
- 启动失败时展示日志位置；从终端双击运行时等待用户按回车关闭，便于阅读错误。
- 启动器不读取、打印或传输 API Key。

## 测试接口

为自动化验证保留三个非默认环境覆盖：

- `WECHAT_EDITOR_PORT`：临时测试端口。
- `WECHAT_EDITOR_LOG_DIR`：临时日志目录。
- `WECHAT_EDITOR_RUNTIME_DIR`：临时 PID 目录。
- `WECHAT_EDITOR_SKIP_OPEN=1`：测试时不调用 macOS `open`。

日常双击不需要设置任何变量。

## 验收标准

- 文件具有可执行权限，`zsh -n` 通过。
- 服务未启动时，双击后能够后台启动并通过 `/api/health`。
- 服务已启动时，再次运行不产生第二个监听进程。
- 非本项目进程占用目标端口时，启动器非零退出且不终止占用进程。
- 成功启动后打开 `http://127.0.0.1:3000`。
- README 同时保留命令行与双击两种启动方式。
